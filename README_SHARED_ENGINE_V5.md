# 大集合：1人用・オンライン共通エンジン版 v5（ルーム入室修正版）

## 今回の入室不具合の修正

入室側のFirebaseキャッシュにルーム情報がないとき、トランザクションの初回コールバックがnullになり、実際には存在するルームへの入室を中止していました。
ルーム情報を先に取得し、初回値がnullでもサーバーの情報による再試行を継続するよう修正しました。確定結果に自分の席があることも確認します。
満員・開始済み・番号違い・異なる版のルームは、理由を個別に表示します。3人制限と同時入室時の席の保護は維持しています。

更新後は作成側・入室側の両方でページを再読み込みしてください。古い画面が残る場合はPCではCtrl+F5、スマートフォンではページを閉じて開き直してください。
同じv5のルーム形式は維持しています。カード効果や保存デッキの処理は今回変更していません。

追加テスト `node tests/join.cjs` で、初回nullと同時入室、満員、存在しない番号、開始済み、異なる版、使用中の番号での作成拒否、入室後の対戦開始を確認しています。
元のv5では同テストの入室に失敗し、修正版では通過することを確認しました。実際のFirebaseプロジェクトへの接続テストは未実施です。

## 更新方法

`index.html`、`online-mode.html`、`effects`フォルダーをまとめて上書きしてください。
今回はHTMLだけの更新では動きません。全参加者が同じv5を使い、更新後は新しいルームを作成してください。
旧版の進行中ルームとは互換性がありません。保存済みデッキ・プレイヤー名・Firebase設定の保存キーは引き継ぎます。

## 今回の変更

- 元の1人用のゲーム処理を `effects/game-engine.js` に移し、両画面から同じファイルを読み込むようにしました。
- ファンファーレ、数字・BP・コストの判定、墓地回収、山札検索、破壊、スペルの処理、革命、ターン進行、効果選択UIを共通化しました。
- オンラインでも各参加者が自分の効果の対象を選択します。ネク・星野アイ・先攻決定は各人の選択を保存し、全員の確定後に一度だけ解決します。
- COMのカード効果も同じ処理を利用します。オンラインのCOM操作はルーム作成者のみが実行します。
- 保存名・保存デッキの共通利用、入室後のデッキ名非表示、革命中のL最強・赤い画面を維持しています。
- 通信処理は `effects/online-adapter.js` に分離しました。更新番号を確認して競合を検出し、古い通信結果による巻き戻りと同時選択の上書きを防ぎます。

「共通化」は元の1人用に実装された処理を基準としています。Excelの文面と違う既存仕様を今回一律に変更するものではありません。
たとえばハッスルねじは元の1人用でも効果が未実装であり、今回新規実装したカードには含めていません。

## 今後の効果追加・修正

| 内容 | 編集先 |
|---|---|
| カード名、数字、BP、コスト、種族、効果文 | `effects/card-catalog.js` |
| デッキ作成に表示するカードの一覧 | `effects/online-card-list.js` |
| 実際の効果、対象選択、数値判定、ターン進行 | **`effects/game-engine.js`** |
| 入室・通信・選択の送受信 | `effects/online-adapter.js` |
| 他の参加者への登場演出 | `effects/online-animations.js` |

カード効果をHTMLや通信ファイルへコピーしないでください。共通エンジンを修正すれば両方に反映されます。
旧 `fanfare-shared.js` は互換用の空ファイルで、どちらの画面も読み込みません。

### 実装時の要点

- `G.players[0]` を操作対象と決めつけず、処理対象の `pi` / `owner` と操作している人の `activeHumanSeat()` を区別してください。
- 人間が対象を選ぶかは `p.human` で判定します。オンラインの他の参加者をCOMとして自動選択してはいけません。
- 選択待ちは `G.pending...` と所有者を保存し、完了まで手番を進めません。UIを新設するときは共通エンジン内で作成し、復元処理 `restoreEffectUI()` にも登録します。
- 効果の解決内容は共通エンジンに一度だけ記述します。新しい「全員同時選択」方式を追加する場合は、共通の解決関数に加えて、通信側の選択検証・確定待ちを接続してください。
- 演出待ちの間は `locked` を立て、効果完了後に解除します。同期送信中に演出が完了しても、その変更を再送します。
- `afterAction(pi)` は効果処理・演出の完了後に呼びます。通信側でカード固有の効果を再実装しないでください。
- 新カード追加後は1人用だけでなく、オンラインの席2・席3から対象を選ぶケースと、2人＋COMを確認してください。

## 検証範囲

- 「オンライン実装〇」53枚の固定条件で、元の1人用／共通化後の1人用／オンラインの状態変化を比較。
- 3人の独立したDOM環境と模擬Firebaseを使用して入室、保存名、先攻決定、パス、ゲストの各種選択、ネク・星野アイの同時確定を確認。
- 実装済みスペル4種、演出後に解決する主要カード、革命表示を確認。
- 2人＋COM、通信応答が演出より遅いケースを確認。

実際のFirebaseプロジェクト・スマートフォン実画面での対戦は未検証です。
固定条件の一致テストは全カードの全組み合わせを保証するものではありません。

## テストの実行

同梱 `tests` はNode.js用です。ゲームの配信自体にNode.jsは必要ありません。
ゲームフォルダーで `npm install --prefix tests` の後、`node tests/network.cjs` と `node tests/com.cjs` を実行できます。
